# 参照画像との一致ゲート（M1〜M6）

**合格ラインを緩めてよいのは人間だけ。** エージェントも Claude も動かさない。
数値は `capture/match-score.json` に残す。**自己申告は受け付けない。**

このゲートが測っているのは「**参照画像に寄っているか**」であって、
「本物に見えるか」ではない。参照画像そのものの出来が上限になる。
報告でこの区別を混同しないこと。

---

## 0. 参照画像の性質（ここを読まずに指標を足さない）

`reference/animals/` の画像は、ChatGPT に次の条件で生成させたもの。
**実物の写真ではない。**

- 正面図と側面図を横並び、**平行投影**、同じ縮尺、足を同じ水平線に揃える
- 背景は真っ白。**影・地面・小物を描かない**
- **フラットなベクター風。陰影グラデーション・質感・毛の描き込みをしない**
- 輪郭線（アウトライン）を描かない

この3点目が指標の設計を決める。**参照に陰影が無いのだから、
陰影の一致は測れない。** 測れないものを測ろうとすると、
「参照に寄せた」つもりで**いま入っている模様を消す**ことになる（M6 参照）。

## 1. 指標と、このラウンドでの扱い

| # | 名前 | 何と比べるか | 扱い |
|---|---|---|---|
| **M1** | シルエット一致 | 参照マスク vs アプリのアルファ | **ゲート**（最優先） |
| **M2** | 体型比率 | `reference/proportions.json` vs ジオメトリ実寸 | **ゲート** |

### 人間が決めたこと（2026-09-06）

**① M1 の画素比較を、静止ポーズに限って許可する。**

CLAUDE.md と計画書は「スクリーンショットの画素比較を合否条件にすること」を
禁じている。M1 はまさにそれに当たるので、次の範囲に限って例外とする。

> `npm run shot -- --pose reference` が撮る**静止1枚**（無背景・シード固定・
> アニメーションなし・平行投影）に限り、画素比較を合否条件にしてよい。
> **動いている場面のスクリーンショット比較は、従来どおり禁止。**

禁止の理由は「動物も背景も常に動くので必ず落ちる」だった。静止ポーズには
その理由が当たらない。ただし**当たらないことを毎回証明する**こと:
同じコードで2回撮ってバイト単位で一致しなければ、M1 は使わない（§3-1）。

**② M4 は落とす。M6 は絶対基準に読み替える。**

- **M4（明暗の構造）** — 参照が平坦なので、明度プロファイルの相関を取る
  相手が無い。今回は測らない。立体感は人間が実機で見る
- **M6（細部の量）** — 「アプリ ÷ 参照」の比を 1 に近づけると、
  参照の高周波がほぼゼロなので**はりねずみのとげ・うしのぶち・
  くまのみのしま模様を消す**ことになる。比ではなく
  「単色の塊になっていないこと」の**絶対下限**として使う

## 2. 合格ライン

**M1・M2・M5 の3つだけをゲートにする。** 6項目を同時に上げると全部中途半端になる。
通ったら M3（配色）、最後に M6（細部）。

| # | 合格ライン | 根拠 |
|---|---|---|
| **M1** | IoU **0.70 以上** | 0.5 は「別の動物」、0.8 は手続き生成では厳しい |
| **M2** | 各比率の相対誤差 **15% 以内** | みずのなかの個体差 ±15% と同じ幅 |
| **M5** | 足元 12px の帯が周囲より **12% 以上**暗い | 影が無いと何を作っても貼り付けに見える |
| M3 | 主要3色の Lab 距離（ΔE76）**12 以内**、面積比の差 15% 以内 | 次段 |
| M6 | マスク内の高周波エネルギー比 **0.02 以上** | 最後。**上限は設けない** |

**これらは Claude が置いた初期値であって、実測に基づく値ではない。**
1体目で通してみて、厳しすぎる／緩すぎると分かったら**人間が動かす**。

### M5 は「参照に寄せる」指標ではない

合格ライン「12% 以上暗い」は参照と比べる値ではなく**絶対値**。
参照画像に影は1枚も無いので、これは「参照に寄せる」話ではなく
**「貼り付けに見えないようにする」**話。混同しないこと。

## 3. 測り方

### 3-1. 同じ向きで撮らないと何も測れない

`npm run shot -- --pose reference` が、参照画像と同じ条件で1枚だけ撮る。

| | 合わせるもの |
|---|---|
| 投影 | **平行投影**（`OrthographicCamera`）。参照が平行投影なので、透視で撮ると輪郭が合わない |
| 向き | `side`（動物が右を向く） / `front` / `three-quarter` |
| 大きさ | 動物の**境界箱の高さ**が画面の一定割合を占めるように正規化する |
| 背景 | 無し（アルファ0）。**アルファチャンネルがそのままマスクになる**ので切り抜きが要らない |
| 光 | `App.ts` と同じ（DirectionalLight 0xfff3e2 1.6 / HemisphereLight 1.1）。ここを変えると M3 が別物を測る |
| 影 | M5 を測るときだけ地面を出す |

**この撮影系が2回続けてバイト単位で一致するまで、見た目を一切いじらない。**
一致しない状態で数値を追いかけると、変化が実装のものか撮影のゆらぎか分からない。

### 3-2. 集計（みずのなかの失敗を繰り返さない）

みずのなかの S1・S2・S5 は連結成分ごとに測って `Math.min` を取っていたため、
**生き物を 2.5倍にしても数値が 0.016% から1ミリも動かなかった**
（葉の隙間から見える細切れが増えるだけだった）。

- **`Math.min` を使わない。** フレーム内は面積で重み付けした中央値
- 複数枚は**下位20%点（p20）**
- 40px 未満の連結成分は測定対象から外す
- 各指標に「何枚中何枚が目標を満たしたか」を併記する

### 3-3. M2 は画素から推定しない

耳や脚の長さを画像から自動計測すると、推定の誤差のほうが測りたい量より大きい。
参照側は `npm run ref-measure` で**人間が数点クリックして比率を確定**し、
`reference/proportions.json` に保存する。アプリ側はジオメトリの実寸から出す。

## 4. 判定の原則

- `capture/match-score.json` の数値だけを見る。**自己申告を受け付けない**
- 数値が動いていないのに「改善した」と書かれていたら、そう指摘する
- **指標が改善に反応しないときは、対象ではなく指標の設計を疑う**
  （みずのなか: 2.5倍にしても数値が動かなかった）
- 参照画像が矛盾している項目は「参照が不定」として**合格に数えず**、人間に報告する
- **参照画像が無い動物は判定しない。触らない**
